# 邻里鲜生（linli-fresh）代码审计报告

**审计日期**：2026-07-06
**审计范围**：`server/`（Express + better-sqlite3 + 自定义鉴权，约 454 个 .js）、`Dockerfile`、`docker-compose.yml`、`docker-entrypoint.sh`、前端三端 `web/`、`admin/`、`leader/`、`rider/`
**审计方式**：静态代码审阅 + 模式搜索（排除 `node_modules`）+ 两个纵深子代理并行审计（安全面 / 质量·依赖·部署面）+ 严重级发现人工复核（已交叉验证）
**结论**：数据访问层安全基线**较好**（SQL 全程参数化、密码用 bcrypt、用户端严格按 token 身份隔离、数据库索引完善）；但**认证/授权边界存在系统性缺陷**，且与「JWT 可预测/可伪造」叠加，足以导致全站被接管。需优先修复。

## 二、🔴 严重 / 🟠 高危发现（必须立即修）

### 1. [严重] 管理后台零权限校验 → 完整越权/提权
- **证据**：`server/app.js:65` 挂载后台用的是普通用户中间件 `authMiddleware`；`server/routes/admin.js` 全文件仅 `require('./middleware/auth')` 的默认导出，**从未引用 `adminAuthMiddleware` 或 `requirePermission`**；`server/middleware/auth.js:71-73` 的 `requirePermission` 含放行逻辑：
  ```js
  // Demo 模式: 用户 token 可访问所有后台接口
  if (!req.adminId && req.userRole === 'user') return next();
  ```
- **后果**：任意已登录普通用户（甚至访客 token 拿到的 userId=1）可直接调用 `/api/v1/admin/*`——改商品价/库存、导出全量用户与订单、查财务、改团长/骑手、删数据。完整权限提升。
- **修复**：后台路由改挂 `adminAuthMiddleware`；删除 `auth.js:71-73` demo 放行；敏感操作叠加 `requirePermission('<perm>')`；`admin` 端必须走独立 `/admin-login` 拿 admin token，禁止复用用户 token。

### 2. [高] JWT 硬编码兜底密钥 → 可伪造任意身份令牌
- **证据**：`server/middleware/auth.js:6`
  ```js
  const JWT_SECRET = process.env.JWT_SECRET || 'linli-fresh-dev-only-secret-change-in-production';
  ```
  且 `docker-compose.yml` 的 `environment` **未设 `JWT_SECRET`**，项目**无 dotenv**（grep 无 `require('dotenv')`）。容器实际用公开字符串签名。
- **后果**：攻击者本地 `jwt.sign({userId:1, role:'admin'}, SECRET)` 即可伪造管理员/任意用户令牌，直接击穿上一项鉴权。
- **修复**：缺失即启动失败（`if(!process.env.JWT_SECRET) throw ...`）；移除非生产兜底串；密钥用 32+ 字节随机值经 secrets 管理下发；引入 `dotenv` 加载 `.env`。

### 3. [高] 代付 token 无签名 + 订单号可枚举 → 匿名泄露他人订单/PII
- **证据**：`server/routes/proxy.js:13-41` token 仅 `base64(orderNo:userId:timestamp)`，无签名/密钥/nonce；`server/helpers.js` 订单号为 `O`+14位时间+4位随机数（每秒 1e4 种，可枚举）；`GET/POST /api/v1/proxy-pay/:token` 挂载时**无 authMiddleware**（匿名）。
  ```js
  function parseProxyToken(token) {
    const decoded = Buffer.from(token, 'base64').toString('utf-8'); // 直接还原，无校验签名
    ...
  }
  ```
- **后果**：攻击者枚举 4 位随机即可伪造 token，匿名读取任意订单商品/金额/收货人姓名·电话·住址（`address_snapshot`），甚至 `POST .../pay` 把他人订单标为已支付。
- **修复**：代付 token 改为服务端 HMAC 签名或一次性随机 uuid 落库（带 `expires_at`/`order_id`）；订单号改用 `nanoid` 不可预测；查询仅返回必要字段并脱敏 PII。

### 4. [高] 财务接口仅校验登录、未校验管理员角色
- **证据**：`server/routes/finance.js` 与 `server/app.js:66` 均只挂 `authMiddleware`。`GET /finance/overview` 返回全平台营收/佣金/退款；`POST /finance/record` 任意登录用户可写入资金流水。
- **后果**：泄露商业机密 + 可伪造流水污染对账。根因同 #1。
- **修复**：`/finance/*` 与 `/admin/*` 统一接入 `adminAuthMiddleware` + `requirePermission('finance')`。

### 5. [高] `uploads/` 目录未持久化（部署问题，容器重建丢图）
- **证据**：`docker-compose.yml:16-18` 仅 `linli-data:/app/server/data`，`server/uploads/`（此前生成的商品图/头像/banner）未挂 volume。
- **后果**：容器重建/升级后 AI 生成图片全部丢失，前端展示位破图。
- **修复**：增加 `linli-uploads:/app/server/uploads` 卷挂载。

## 四、🟢 低风险 / 观察项

- `helpers.error()` 业务错误一律返回 **HTTP 200**（仅 `code` 字段标 401/403/404），前端/网关/监控按状态码重试·熔断·告警全部失效 → 建议 `error(res,msg,httpStatus=400)`。（来源：质量审计 E1）
- `routes/proxy.js:146`、`admin.js:1068` 等 `catch` 把内部异常原文返回未认证调用方（信息泄露）。（E3）
- `middleware/rateLimit.js:18` 限流 key 含完整 path（`ip:path`），对 `/orders/123` 类路径实际无限流；登录接口无专门限流防爆破。（C3）
- 订单状态/会员阈值等魔法数字无常量定义，难维护。（C2）
- `Dockerfile` 以 root 运行、基础镜像 `node:20-bookworm-slim` 未锁 digest。（K2/K3）
- `docker-entrypoint.sh` 中 `seed.js` 失败会致容器崩溃循环（建议幂等兜底）。（K5）
- `package.json` 用 caret 范围，建议 CI 跑 `npm audit` 锁精确版本。（D1）

## 五、✅ 做得好的地方（避免误报）

- **SQL 注入**：全部 `db.prepare` 用 `?` 占位符；动态 UPDATE 字段名来自硬编码白名单（`admin.js`、`user.js`）；`IN (${placeholders})` 占位符由 `.map(()=>'?')` 生成并参数化。
- **命令注入/路径遍历**：无 `child_process`/`exec`/`multer`/路径拼接用户输入。
- **密码哈希**：注册/登录/管理员登录均 `bcryptjs` 12 轮，无明文/弱哈希。
- **用户端 IDOR**：订单/地址/购物车/消息/拼团查询全部按 `req.userId`（token 身份）过滤，无越权。
- **依赖安全**：`package-lock.json` 存在（lockfileVersion 3）；express 4.22.2、jsonwebtoken 9.0.3、nanoid 3.3.15 等核心库版本健康，无未使用直接依赖。
- **数据库索引**：`db.js` 建表建立 50+ 索引，覆盖主流查询字段。
- **无死代码同步 I/O / 无 TODO 技术债**：源码无 `readFileSync` 阻塞、无 TODO/FIXME 注释。
