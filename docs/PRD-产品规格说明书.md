## 一、文档概述

### 1.1 编写目的

本文档是「邻里鲜生」社区在线超市项目的核心产品规格说明书，用于统一团队对产品方向、功能边界、业务流程和技术实现的认知。文档覆盖从用户下单到团长履约、从在线支付到数据复盘的全链路，作为研发排期、UI 设计、测试用例编写和运营策略制定的基准。

### 1.2 术语表

| 术语 | 定义 |
|------|------|
| 前置仓 | 位于社区周边 3 公里范围内的微型仓储点，承担分拣、暂存和骑手取货功能 |
| 团长 | 社区内的兼职运营者，负责开团、社群维护和订单归集，按成交额获得分佣 |

| 子女代付 | 老人下单、子女远程代付的功能模式 |
| SKU | 库存量单位，指单品的最小管理单元 |
| LTV | 用户生命周期价值 |
| GMV | 商品交易总额 |

## 二、产品背景与愿景

### 2.1 业务背景

生鲜购买是中国家庭最高频的消费行为之一，社区家庭平均每周采购 3.2 次。然而城市化进程让"买菜"这件事变得越来越不方便：菜场晚八点收摊，年轻人加班回家往往扑空；大型超市排队结账动辄半小时；传统电商次日达又满足不了"今晚要吃"的即时需求。与此同时，小区社区群里每天都在发生分散的邻里互助——谁家多了两斤番茄愿意分享，谁家带回土鸡蛋想分邻居——这些真实的社区善意，缺乏一个可沉淀、可规模化的产品载体。

### 2.2 产品愿景

邻里鲜生不做"更大的超市"，而做"更近的菜场"。以单个小区为最小运营单元，把前置仓铺进三公里生活圈，让每一栋楼都像拥有一个"共享冰箱"。门面是 Web 应用，浏览器访问即用；收银是在线支付（支付宝/微信 H5 支付），从看货到付款一气呵成；客流来自社区群，团长发一条拼团链接，邻居们点开就买。把被现代生活挤压掉的买菜便利，一点点还回来。

### 2.3 核心价值主张

| 维度 | 价值 |
|------|------|
| 对用户 | 30 分钟送达，买菜从"出门任务"变成"顺手小事"，每天省下约 30 分钟 |
| 对社区 | 团长即邻居，拼团即社交，用"吃"重新连接邻里关系 |
| 对团长 | 灵活就业渠道，零门槛创业，闲置时间与信任转化为收入 |
| 对小商户 | 零代码接入 Web 应用和在线支付，把熟客关系沉淀为线上订单 |

### 2.4 不做清单（产品边界）

为确保 MVP 阶段资源聚焦，以下方向明确不在首期范围内：

- 不做自建供应链的产地直采（首期采用区域批发商供货）
- 不做跨城配送（服务范围严格限定在单城社区）
- 不做独立 App（仅 Web 应用一个用户入口）
- 不做餐饮外卖（只卖生鲜和日用品，不做熟食现做）
- 不做 B2B 批发（不面向餐厅、食堂供货）

### 3.1 市场规模与趋势

| 移动支付月活用户 | 支付宝+微信支付合计超 10 亿 | 公开数据 |

### 3.2 目标市场定义

**地理范围：** 一二线城市的中大型社区（入住率 60% 以上、户数 1000+），优先选择年轻家庭占比高、周边菜场覆盖不足的区域。

**用户规模估算：** 单个社区按 2000 户、户均 2.8 人计算，目标渗透率 15%，则单社区目标用户约 840 人。

### 3.3 竞争格局

| 竞品类型 | 代表 | 优势 | 劣势 | 我们的差异化 |
|----------|------|------|------|-------------|
| 综合生鲜电商 | 叮咚买菜、美团买菜 | SKU 丰富、资金雄厚、品牌认知度高 | 流量逻辑冰冷、缺乏社区温度、获客成本高 | 人情味与信任，团长即邻居 |
| 社区团购平台 | 多多买菜、淘菜团 | 价格极低、覆盖广 | 次日自提、品控参差、团长流动性大 | 30 分钟送达 + 品质背书 |
| 传统菜场 | 线下农贸市场 | 新鲜可见、可挑可选 | 营业时间固定、环境参差、无配送 | 即时配送 + 线上选品 |
| 小区便利店 | 夫妻店、社区超市 | 近、熟人关系 | SKU 有限、无线上能力、营业时间受限 | 全品类 + 数字化 + 即时达 |

### 3.4 入场时机

移动 Web + 在线支付的生态成熟度已足够支撑即时零售闭环；社区团购教育了用户"小区拼单"的心智，但履约时效仍是痛点。邻里鲜生以"即时达"切入，正好承接已被教育的用户需求，同时解决时效短板。

## 四、用户画像与需求

### 4.1 用户分层

| 用户类型 | 占比预估 | 使用频次 | 客单价 | 核心诉求 |
|----------|----------|----------|--------|----------|
| 宝妈/家庭主妇 | 45% | 每周 3-5 次 | 35-60 元 | 新鲜、安全、省时、可信赖 |
| 城市白领 | 35% | 每周 2-3 次 | 25-45 元 | 极速、方便、无需出门 |
| 银发群体（含子女代付） | 20% | 每周 1-2 次 | 30-50 元 | 简单、有人情味、子女放心 |

### 4.2 详细用户画像

#### 4.2.1 宝妈/家庭主妇

**基本信息：** 28-40 岁，已婚有孩，全职或弹性工作，家庭日常采购的主要决策者。

**典型场景：** 上午送完孩子上学，回家路上打开社区群，看到团长刚发的"今日基地直采"拼团链接，顺手把今晚的青菜、明天的鸡蛋、下周的米面一起下单。中午前骑手送到楼下，不耽误接孩子、不耽误做饭。周末在群里和其他宝妈交流辅食做法，顺手拼个有机蔬菜箱。

**核心痛点：**
- 没空专门跑菜场挑菜，担心网购生鲜不新鲜、孩子吃了不安全
- 大平台冷链运输到家常常化冻，品质时好时坏
- 价格虽然敏感，但更怕"便宜没好货"

**我们的价值：**
- 团长是同小区相熟的邻居，自己孩子也在吃，品质有真人背书
- 社群里每天都有邻居真实晒单、讨论哪家好吃
- 前置仓就在三公里内，半小时送达、当天采当天卖

#### 4.2.2 城市白领

**基本信息：** 25-35 岁，租房或刚置业，工作节奏快，下班时间晚，对效率极度敏感。

**典型场景：** 加班到晚上八点，挤上地铁才想起家里没菜。掏出手机打开浏览器访问 Web 应用，选好明早的牛奶面包和今晚的速食，在线支付一键买单。出地铁、走回家，骑手的电话正好打来——菜已送到门口。从下单到开火，全程不超过四十分钟。

**核心痛点：**
- 菜场早已收摊，超市晚上九点还在排队
- 回家再出门买菜身心俱疲
- 大电商次日达满足不了"今晚就要吃"的即时需求
- 下载一堆 App、注册绑卡、记密码，门槛太高

**我们的价值：**
- 30 分钟极速达，比外卖还快
- Web 应用浏览器访问即用，免安装即买
- 在线支付一键完成，全程在浏览器内闭环
- 前置仓就在公司或家附近，超时自动赔付

#### 4.2.3 银发群体（子女代付场景）

**基本信息：** 60 岁以上，与子女同住或独居，部分会使用智能手机基础功能，但对复杂操作和支付绑定有恐惧心理。

**典型场景：** 老人在家想买点新鲜菜，但不会用智能手机、不敢绑卡支付。在外地工作的子女打开 Web 应用，用老人的收货地址下单，自己在线支付远程付款。团长送货上门时顺便问候一句"阿姨今天气色不错"，老人开心，子女在外也安心。逢年过节，子女还能远程给父母下个"年货礼盒"。

**核心痛点：**
- App 操作太复杂，字小、按钮多、流程长
- 不会绑定银行卡、害怕输错密码、担心被骗
- 子女不在身边，老人买菜只能靠自己腿脚

**我们的价值：**
- 子女代付功能，让远在他乡的儿女也能照顾父母的餐桌
- 团长上门送菜，顺便一句问候、帮拎上楼
- Web 应用界面极简、大字版可选，老人自己也能学着用

### 4.3 用户需求优先级

| 需求 | 用户群体 | 优先级 | 备注 |
|------|----------|--------|------|
| 30 分钟内送达 | 全部 | P0 | 核心差异化 |
| 在线支付一键买单 | 全部 | P0 | 体验闭环 |
| 团长品质背书 | 宝妈、银发 | P0 | 信任基础 |
| 子女代付 | 银发 | P1 | 情感价值高 |
| 拼团优惠 | 全部 | P1 | 裂变与复购 |
| 大字版界面 | 银发 | P2 | 适老化 |
| 会员积分 | 宝妈 | P2 | LTV 提升 |

## 五、产品定位

### 5.1 一句话定位

以社区为单元的 Web 应用即时生鲜超市，30 分钟送达，由邻居团长运营。

### 5.2 三个核心差异化

| 差异化 | 说明 |
|--------|------|
| 精准 | 千区千面的选品与推荐，老旧小区多粮油、年轻社区多速食，每个社区的 SKU 结构都根据住户画像动态调整 |
| 即时 | 前置仓 + 社区骑手，平均 30 分钟从仓到桌，超时自动赔付 |
| 有温度 | 团长即邻居，推荐即背书，复购靠信任而非优惠券 |

### 5.3 服务范围

- **地理范围：** 单个前置仓覆盖半径 1.5-3 公里，约 3-5 个中大型社区
- **配送时效：** 标准订单 30 分钟达，拼团订单按成团时间集中配送
- **营业时间：** 07:00-22:00，与前置仓营业时间同步
- **起送门槛：** 0 元起送，配送费按距离阶梯定价（近距离免配送费）

## 六、核心功能规格

### 6.1 功能总览表

| # | 模块 | 功能点 | 功能描述 |
|---|------|--------|----------|
| 1 | 用户端-首页 | 社区定位与切换 | 自动定位最近社区，支持手动切换；展示当前社区名称、配送范围、预计送达时间 |

| 4 | 用户端-首页 | Banner 轮播 | 顶部轮播位展示营销活动、拼团预告、新品上架；支持点击跳转 |
| 5 | 用户端-首页 | 搜索 | 支持商品名称、拼音首字母搜索；展示搜索历史与热门搜索；搜索结果按销量/价格/好评排序 |
| 6 | 用户端-购物车 | 加购/减购 | 商品卡片点击"+"直接加入购物车；购物车支持数量增减、单品删除、清空 |

| 8 | 用户端-下单 | 订单确认页 | 展示商品清单、收货地址、配送时间选择、优惠券选择、实付金额；支持备注 |

| 12 | 用户端-支付 | 子女代付 | 老人下单后生成代付链接，通过短信/邮件分享给子女；子女点击链接完成支付 |
| 13 | 用户端-支付 | 优惠券核销 | 订单页自动匹配可用优惠券；支持 Web 优惠券一键领取与使用 |
| 14 | 用户端-订单 | 订单列表 | 按"全部/待付款/待配送/配送中/已完成"筛选；展示订单号、商品缩略图、金额、状态 |
| 15 | 用户端-订单 | 订单详情 | 展示商品明细、配送信息、支付信息、物流轨迹（骑手位置实时更新） |
| 16 | 用户端-订单 | 售后申请 | 支持"缺货/质量问题/送错/其他"原因退款/退货；团长审核后原路退回 |

| 18 | 用户端-会员 | 会员中心 | 展示会员等级、积分余额、优惠券列表、消费记录 |
| 19 | 用户端-会员 | 积分体系 | 消费 1 元积 1 分；积分可兑换优惠券或实物；每日签到额外积分 |

| 27 | 团长端-工作台 | 社群模板消息 | 提供"今日上新""特价提醒""到货通知"等模板，一键生成文案+分享链接 |
| 28 | 团长端-工作台 | 客户管理 | 查看本社区客户列表、消费频次、偏好商品；支持按标签分组 |
| 29 | 运营后台-商品 | 商品库管理 | 新增/编辑/上下架商品；维护商品名称、规格、价格、库存、分类、主图、详情图 |

| 35 | 运营后台-营销 | 会员规则配置 | 设置会员等级门槛与权益（如 Lv.2 免配送费、Lv.3 专属折扣） |
| 36 | 运营后台-数据 | 销售数据看板 | 实时 GMV、订单量、客单价、热销榜、复购率；支持按日/周/月/社区维度筛选 |
| 37 | 运营后台-数据 | 用户数据看板 | 新增用户、活跃用户、留存率、LTV、用户分群 |
| 38 | 运营后台-团长 | 团长招募与管理 | 团长申请审核、账号开通、覆盖社区绑定、佣金比例设置、绩效排名 |
| 39 | 运营后台-财务 | 资金对账 | 支付宝/微信支付 T+1 账单自动导入；订单金额、佣金、平台收入的自动拆分与对账 |
| 40 | 运营后台-系统 | 权限管理 | 角色（超级管理员/运营/财务/客服）的菜单与数据权限配置 |

### 6.2 用户端（Web 应用）功能详述

#### 6.2.1 首页与商品浏览

**页面原型说明：**

首页采用标准的 Web 垂直滑动布局，从上到下依次为：社区信息栏 → 搜索栏 → Banner 轮播 → 分类导航栏 → 商品列表。

**功能逻辑：**

- **社区定位：** 用户首次打开 Web 应用时，调用浏览器 Geolocation API 获取经纬度，匹配最近的前置仓覆盖社区。若定位失败或用户拒绝授权，引导手动选择城市与社区。用户手动切换社区时，商品列表、库存、价格均需重新拉取。
- **分类导航：** 一级分类固定为 8 个，横向滑动展示。切换分类后，商品列表切换为对应分类下的商品，按"销量降序"默认排序。
- **商品卡片：** 每张卡片包含商品主图（正方形，1:1）、商品名称（最多两行，超出截断并加省略号）、规格（如"1kg/箱"）、现价（加粗，主色）、原价（划线，灰色）、销量（如"已售 342"）。标签最多展示 2 个，优先级：团长推荐 > 今日特价 > 新品 > 热销。
- **缺货状态：** 库存为 0 时，商品图叠加 50% 透明度灰色蒙层，居中显示"补货中"标签；加购按钮置灰不可点。
- **Banner：** 支持 3-5 张轮播，自动播放间隔 4 秒，支持手动滑动。点击后跳转：活动页、拼团详情页、商品详情页或外部 H5。
- **搜索：** 搜索框常驻在首页顶部，点击后进入搜索页。输入时实时联想（防抖 300ms），展示匹配商品列表。无结果时展示"暂无相关商品，为您推荐"+热销商品。

**边界与异常：**

- 网络超时：商品列表加载失败时，展示"网络开小差了"插图 + "点击重试"按钮
- 社区无覆盖：若用户定位位置不在任何前置仓配送范围，展示"您附近暂未开通服务"页面，提供"预约开通"按钮（收集手机号与小区名称）
- 空状态：某分类下无商品时，展示"该分类暂无商品，去别处逛逛"引导至其他分类

#### 6.2.2 商品详情页

**功能逻辑：**

- **信息展示：** 商品轮播图（最多 6 张）、商品名称、规格选择器（如 500g/1kg，不同规格价格不同）、价格、销量、产地、储存方式、商品详情图/文。
- **规格选择：** 点击规格按钮弹出底部面板，选择后价格联动更新。未选择规格时，"加入购物车"按钮置灰。
- **团长推荐语：** 若该商品被当前社区团长标记为推荐，在详情页中部展示团长头像+昵称+推荐语（如"我家孩子吃了三箱，真的甜"）。
- **邻居评价：** 展示该商品在本社区的购买评价（仅展示有文字或图片的评价），按"最新"排序。默认展示 3 条，点击"查看更多"展开全部。
- **相关推荐：** 详情页底部展示"买过这件的人还买了"的关联商品列表。

**交互逻辑：**

- 点击商品卡片 → 进入商品详情页
- 选择规格 → 点击"加入购物车" → 底部弹出"已加入购物车"toast，购物车数字 +1
- 点击"立即购买" → 跳过购物车，直接进入订单确认页（仅含该商品）

#### 6.2.3 购物车

**功能逻辑：**

- **浮层入口：** 首页及分类页底部常驻购物车浮层，显示商品总件数（数字角标）与合计金额。点击后从底部滑出购物车面板。
- **面板内操作：** 展示商品缩略图、名称、规格、单价、数量步进器（- / +）、删除按钮。数量最小为 1，最大为当前库存。
- **结算按钮：** 面板底部显示"合计：¥XX.XX"与"去结算"按钮。商品总件数为 0 时，按钮置灰显示"购物车是空的"。
- **失效商品：** 若购物车内商品已下架或库存不足，该条目置灰，移至列表底部，标注"已失效"，提供"清除失效商品"按钮。

**边界与异常：**

- 库存不足：用户加购后，商品被其他用户买完，购物车中该商品条目显示"库存不足，仅剩 X 件"，数量自动修正为库存最大值
- 社区切换：用户切换社区后，购物车清空并提示"切换社区后购物车已重置"

#### 6.2.4 订单确认页

**功能逻辑：**

- **商品清单：** 展示购物车中所有商品（缩略图、名称、规格、数量、小计），支持点击返回修改购物车。
- **收货地址：** 默认展示最近使用地址，点击后进入地址列表。地址卡片展示联系人、手机号、详细地址（精确到门牌号）。无地址时，引导新增地址。
- **配送时间：** 两个选项——"尽快送达（预计 XX:XX 前）"与"预约配送"（时间选择器，以 30 分钟为粒度，可选未来 2 天内时段）。默认选中"尽快送达"。
- **优惠券：** 自动匹配一张最优优惠券并展示（如"已为您选择最优券：满 30 减 2"）。点击后展开优惠券列表，展示可用券与不可用券（灰色，标注不可用原因如"未达门槛"）。
- **备注：** 单行文本输入，最多 50 字，placeholder"给团长留言，如'请帮我把鸡蛋装结实一点'"。
- **金额计算：** 商品小计 + 配送费 - 优惠券抵扣 = 实付金额。配送费规则：订单满 29 元免配送费，否则 3 元。
- **提交订单：** 点击后校验地址、库存、优惠券有效性，校验通过生成待支付订单，跳转支付页。

**规则约束：**

- 订单金额必须大于 0 元
- 单个订单最多包含 20 件商品（含重复 SKU 的累计数量）
- 优惠券需在有效期内且满足使用门槛
- 预约配送时段的库存需单独预留，若该时段运力已满，该时段置灰不可选

#### 6.2.5 Web 支付与子女代付

**功能逻辑：**

- **标准支付：** 订单确认后，跳转到 Web 支付页面，支持支付宝/微信 H5 支付收银台。用户选择支付方式（余额/银行卡）后完成支付。支付成功后，Web 推送通知/短信通知推送"支付成功"消息，Web 应用跳转"支付成功"页。
- **支付超时：** 订单生成后 15 分钟内未支付，自动取消订单，库存释放。支付页倒计时展示剩余时间。
- **支付失败：** 用户取消支付或余额不足，返回订单确认页，保留订单信息，允许重新发起支付。
- **子女代付流程：**
  1. 老人在订单确认页选择"让子女帮我付"
  2. 系统生成代付链接（带订单标识的 Web 页面地址）
  3. 老人通过短信/邮件将链接发送给子女
  4. 子女点击链接进入 Web 代付页，确认订单信息后完成支付
  5. 支付成功后，老人和子女均收到 Web 推送通知/短信通知

**边界与异常：**

- 代付链接有效期：24 小时，超时后老人需重新发起代付
- 代付订单被部分支付：若订单金额变更（如优惠券失效），代付链接自动失效，需重新发起

#### 6.2.6 订单管理与物流

**功能逻辑：**

- **订单列表：** 顶部 Tab 切换"全部/待付款/待配送/配送中/已完成"。每张订单卡片展示：订单号、状态标签、商品缩略图（最多 3 张，超出显示"+N"）、商品总数、实付金额、操作按钮。
- **状态流转：**
  - 待付款：展示"去支付"（倒计时）和"取消订单"按钮
  - 待配送：展示"申请退款"按钮
  - 配送中：展示骑手信息（头像、姓名、电话）与实时位置地图（调用腾讯地图 SDK）
  - 已完成：展示"再来一单"和"申请售后"按钮
- **订单详情：** 完整展示商品明细、配送信息、支付流水号、下单时间、支付时间。

**状态机：**

```
[下单] → 待付款 → （15分钟内支付）→ 待配送 → （骑手接单）→ 配送中 → （送达确认）→ 已完成
                         ↓                        ↓
                    （超时未付）              （用户申请退款）
                         ↓                        ↓
                       已取消               售后处理中 → 已退款/已拒绝
```

#### 6.2.7 拼团功能

**功能逻辑：**

- **拼团入口：** 首页 Banner 下方有"邻里拼团"入口卡片；商品列表中拼团商品有"拼团价"标签。
- **拼团列表页：** 展示当前社区进行中的所有拼团，每张卡片包含：商品图、商品名称、拼团价（大字）、原价（划线）、目标人数、已参团人数、剩余名额、倒计时（截止时间）。
- **拼团详情：** 展示商品信息、拼团规则（几人成团、截止时间）、当前参团成员头像列表（最多展示 8 个，超出"+N"）、参团进度条。
- **参团流程：** 点击"立即参团" → 选择规格 → 确认订单（拼团价自动生效） → 支付 → 参团成功。支付成功后展示"参团成功"页，提示"还差 X 人成团"，提供"邀请邻居"按钮生成分享链接。
- **成团与失败：** 达到目标人数后自动成团，系统通知所有参团用户"拼团成功，准备配送"。截止时未达人数则拼团失败，自动原路退款，通知用户"拼团失败，款项已退回"。

**规则约束：**

- 单个拼团活动有效期最长 48 小时
- 每人每单拼团限购 1 件（防止团长刷单）
- 拼团商品不可使用优惠券（价格已为拼团价）
- 成团后统一配送，不单独发即时达

#### 6.2.8 会员与积分

**功能逻辑：**

- **会员等级：**
  - Lv.1 新邻居：注册即获得
  - Lv.2 老熟人：累计消费满 199 元
  - Lv.3 老街坊：累计消费满 999 元且下单 10 次以上
- **等级权益：**
  - Lv.2：每月 2 张免配送费券、生日礼券
  - Lv.3：每月 4 张免配送费券、专属 95 折、优先客服
- **积分获取：** 消费 1 元积 1 分（拼团商品按拼团价积分），每日签到 +5 分，首次评价 +10 分
- **积分消耗：** 积分商城兑换优惠券（100 分 = 1 元抵扣）或实物商品

### 6.3 团长端（H5 工作台）功能详述

团长端采用 H5 页面，团长通过浏览器访问，无需下载独立 App。

#### 6.3.1 今日数据看板

**功能逻辑：**

- 顶部展示核心数据卡片：今日订单数、今日成交额（元）、今日佣金（元）、待处理订单数
- 每个卡片对比昨日同期，展示增长/下降百分比（绿色向上箭头/红色向下箭头）
- 中部折线图展示近 7 天订单量趋势（数据由后台提供）
- 底部"快捷入口"：一键开团、订单管理、佣金提现、社群消息

#### 6.3.2 一键开团

**功能逻辑：**

- **选择商品：** 从平台商品池中选择要拼团的商品，支持按分类筛选与搜索。每种商品展示平台建议拼团价（低于零售价 10%-20%）。
- **设置参数：**
  - 拼团价：团长可在平台建议价基础上微调（浮动范围 ±10%，超出需平台审核）
  - 成团人数：2-50 人
  - 截止时间：默认 24 小时后，最长 48 小时
  - 限购数量：默认不限，可设置每人限购 X 件
- **生成分享：** 确认后生成分享链接（包含商品图、拼团价、剩余名额），团长可一键分享到社区群或朋友圈。
- **开团限制：** 每位团长同时最多开展 5 个拼团活动；同一商品在同一社区 24 小时内不可重复开团。

#### 6.3.3 订单管理

**功能逻辑：**

- **订单列表：** 展示本社区所有订单，按状态筛选（待配送/配送中/已完成/售后中）。
- **配送标记：** 对于"自提"订单，团长在货物到达后标记"已到团长处"，用户收到通知前来领取。对于"直送到户"订单，骑手配送完成后状态自动变更。
- **售后处理：** 用户发起售后申请后，团长在 24 小时内审核。审核通过则提交平台退款；审核拒绝需填写拒绝原因。
- **订单通知：** 新订单到达时，通过 Web 推送通知/短信通知提醒团长。

#### 6.3.4 佣金与提现

**功能逻辑：**

- **佣金规则：** 团长从每笔成交订单中获得佣金，标准商品佣金率 8%-12%（平台按品类设定），拼团商品佣金率 5%-8%。
- **佣金明细：** 列表展示每笔佣金的来源订单、商品、金额、结算状态（待结算/已结算/已提现）。
- **结算周期：** T+1 结算（订单完成次日），拼团订单为成团且全部完成配送后次日。
- **提现：** 团长发起提现申请，金额转入支付宝/微信账户。单笔提现最低 10 元，最高 5000 元，每日限提 3 次。提现申请实时到账（平台预充值资金池）。

#### 6.3.5 社群运营工具

**功能逻辑：**

- **模板消息库：** 提供 8 种预设模板：
  1. 今日上新："XX 小区今日上新，新鲜直达"
  2. 特价提醒："XX 商品限时特价，手慢无"
  3. 到货通知："您订阅的 XX 已到货"
  4. 拼团召集："还差 X 人成团，快来"
  5. 周末福利："周末特别推荐"
  6. 天气关怀："降温了，火锅食材备起来"
  7. 晒单邀请："收到货的邻居来晒个单"
  8. 节日问候：节气/节日专属文案
- **一键发送：** 选择模板后，系统自动填充当前社区热销商品/活动信息，生成文案 + 分享链接，团长确认后直接调起分享。
- **发送记录：** 记录每次发送的模板、时间、内容，方便团长避免重复发送。

#### 6.3.6 客户管理

**功能逻辑：**

- **客户列表：** 展示本社区所有下过单的客户，包含头像、昵称、手机号（若有）、累计消费金额、下单次数、最近下单时间。
- **标签管理：** 团长可给客户打标签，如"常客""宝妈""爱买水果""价格敏感"，便于精准运营。
- **客户分群：** 按消费频次自动分群——高价值（消费 TOP20%）、活跃（近 7 天有下单）、沉睡（30 天未下单）。对沉睡客户可一键发送唤醒优惠券。

### 6.4 运营后台（PC Web）功能详述

#### 6.4.1 商品与库存管理

**功能逻辑：**

- **商品库：** 维护平台全部商品信息，字段包括：商品 ID、名称、副标题、分类（三级）、规格（支持多规格矩阵）、价格、成本价（内部）、库存、产地、供应商、上下架状态、商品标签、主图（最多 1 张）、详情图（最多 6 张）。
- **批量操作：** 支持 Excel 批量导入/导出商品；批量上下架；批量改价；批量调库存。
- **千区千面选品：** 为每个社区配置"商品池"，从总商品库中勾选该社区可售商品。支持按社区标签批量应用选品模板：
  - 老小区模板：粮油调味占比 35%、日用百货占比 25%
  - 年轻社区模板：速食半成品占比 30%、零食饮料占比 25%
  - 高端社区模板：有机进口占比 30%、精品水果占比 25%
- **库存管理：** 实时同步各前置仓库存。设置库存预警阈值（默认低于 20 件预警），预警时向运营人员推送通知。支持手动补货登记与库存盘点。

#### 6.4.2 订单与配送调度

**功能逻辑：**

- **订单看板：** 全量订单列表，支持按城市、前置仓、社区、状态、时间范围筛选。展示订单号、用户信息、商品清单、金额、支付方式、配送地址、骑手、状态。
- **自动派单：** 订单进入"待配送"状态后，系统根据骑手位置、当前订单量、配送距离自动派单。派单逻辑：优先分配给距离最近且当前订单 <3 单的骑手。
- **手动干预：** 运营人员可手动改派骑手、取消订单、修改订单金额（需审批）。
- **异常处理：** 标记异常订单（如骑手拒单、用户电话不通、地址错误），转入客服跟进队列。
- **骑手管理：** 骑手档案（姓名、电话、身份证号、配送范围、工作状态）、排班表、绩效统计（日/周/月单量、准时率、差评率、投诉次数）。

#### 6.4.3 营销工具

**功能逻辑：**

- **优惠券配置：** 创建优惠券时设置：名称、类型（满减/折扣/免配送费）、面额/折扣率、使用门槛、有效期类型（固定日期/领取后 N 天有效）、发放总量、每人限领数量、适用商品范围（全部/指定分类/指定商品）、适用社区范围。
- **发放方式：** 新人自动发放、手动发放（指定用户名单）、活动页领取、拼团成功奖励、签到奖励。
- **会员规则：** 配置会员等级门槛（累计消费金额 + 下单次数）、等级名称、等级权益（折扣率、每月免配送费次数、专属客服等）。
- **Banner 管理：** 配置首页轮播图，设置跳转目标（商品详情/活动页/拼团页/外部 H5）、展示顺序、有效期、展示社区范围。

#### 6.4.4 数据报表

**功能逻辑：**

- **实时数据大屏：** 展示当日累计 GMV、订单量、客单价、新增用户、活跃用户数，数据每 5 分钟刷新。
- **销售分析：**
  - 趋势分析：GMV/订单量/客单价的日/周/月趋势图
  - 品类分析：各分类销售额占比、TOP20 热销商品、滞销商品预警
  - 社区分析：各社区的 GMV、渗透率、复购率排名
- **用户分析：**
  - 新增用户趋势、用户来源分布（搜索/分享/链接访问/老带新）
  - 留存率：次日/7 日/30 日留存
  - LTV 分群：不同获取渠道的用户生命周期价值对比
- **团长分析：** 各团长的订单量、成交额、佣金、拉新人数、活跃度排名

#### 6.4.5 团长管理

**功能逻辑：**

- **招募审核：** 展示团长申请列表，包含申请人信息（姓名、电话、所在社区、申请理由）、审核状态。运营人员可"通过"或"拒绝"（需填写拒绝原因）。
- **团长档案：** 团长基本信息、覆盖社区、历史业绩、佣金余额、提现记录、违规记录。
- **佣金比例设置：** 支持按团长/按品类/按社区三个维度设置差异化佣金率。
- **团长淘汰机制：** 连续 30 天无开团或无订单的团长，系统自动标记为" inactive"，暂停其开团权限，由运营人员决定是否清退。

#### 6.4.6 财务与对账

**功能逻辑：**

- **资金流水：** 记录每一笔支付、退款、佣金结算、提现的流水，包含：流水号、类型、金额、关联订单、时间、对方账户。
- **T+1 对账：** 每日自动从支付宝/微信支付商户平台拉取前一日账单，与系统订单进行自动核对。对平/差异订单列表展示，差异订单标记原因（如"用户支付后未回调"）。
- **收入拆分：** 每笔订单自动拆分为：商品成本、平台收入、团长佣金、配送成本。按日/周/月汇总。

#### 6.4.7 权限管理

**功能逻辑：**

- **角色定义：**
  - 超级管理员：全部权限
  - 运营经理：商品、订单、营销、数据、团长管理
  - 财务人员：资金对账、提现审核、收入报表
  - 客服：订单查询、售后处理、用户查询（不可修改）
  - 城市经理：仅限被分配城市的订单、社区、数据
- **操作日志：** 记录后台所有人员的增删改操作，包含操作人、时间、操作内容、操作前数据快照（用于审计）。

## 七、业务流程

### 7.1 标准购物流程

```
用户打开 Web 应用
    ↓
自动定位/选择社区 → 展示该社区商品
    ↓
浏览商品/搜索商品 → 加入购物车
    ↓
进入购物车 → 确认商品与数量
    ↓
点击"去结算" → 进入订单确认页
    ↓
选择收货地址、配送时间、优惠券
    ↓
点击"提交订单" → 生成待支付订单（15分钟有效）
    ↓
跳转到 Web 支付页面 → 用户完成支付
    ↓
订单状态变为"待配送" → 系统派单给骑手
    ↓
骑手接单取货 → 订单状态变为"配送中"
    ↓
骑手送达 → 用户确认收货（或系统自动确认，24小时后）
    ↓
订单完成 → 触发佣金结算（T+1）
```

### 7.2 拼团流程

```
团长在 H5 工作台选择商品 → 设置拼团价/人数/截止时间
    ↓
生成拼团活动 → 团长分享链接到社区群/朋友圈
    ↓
邻居点击链接 → 进入拼团详情页
    ↓
选择规格 → 支付参团（拼团价）
    ↓
参团人数达到目标 → 拼团成功
    ↓
系统通知所有参团用户 → 订单进入"待配送"
    ↓
前置仓统一拣货 → 集中配送（成团后 4 小时内）
    ↓
送达后用户确认 → 订单完成

（分支：截止时间到未成团）
    ↓
系统自动退款（原路返回）→ 通知用户"拼团失败"
```

### 7.3 子女代付流程

```
老人在订单确认页选择"让子女帮我付"
    ↓
系统生成代付链接
    ↓
老人通过短信/邮件发送给子女
    ↓
子女点击链接 → 进入代付确认页（展示订单详情）
    ↓
子女点击"确认代付" → 跳转到 Web 支付页面
    ↓
支付成功 → 老人收到"订单已支付"通知
    ↓
订单进入正常配送流程
```

### 7.4 售后退款流程

```
用户在订单详情页点击"申请售后"
    ↓
选择退款原因（缺货/质量问题/送错/其他）+ 上传照片（可选）
    ↓
提交申请 → 状态变为"售后处理中"
    ↓
团长审核（24小时内）
    ↓
（审核通过）→ 提交平台退款 → 原路退回 → 通知用户
    ↓
（审核拒绝）→ 填写拒绝原因 → 通知用户 → 用户可再次申请或联系客服
```

### 7.5 团长提现流程

```
团长在 H5 工作台点击"提现"
    ↓
输入提现金额（≥10元，≤可提现余额）
    ↓
确认提现 → 系统校验金额与次数限制
    ↓
通过支付宝转账/微信企业付款 → 实时转入团长账户
    ↓
团长收到"提现到账"通知
    ↓
更新佣金明细状态为"已提现"
```

## 八、技术架构

### 8.1 系统架构概述

采用三层架构：前端层负责用户交互，中台层负责业务逻辑与智能调度，后台层负责数据存储与资金对账。整体基于微服务设计，支持水平扩展。

### 8.2 前端层

| 模块 | 技术方案 | 说明 |
|------|----------|------|
| 用户端 | Vue 3 + Vite SPA 应用 | 浏览器访问即用；调用 Web 能力（在线支付、Geolocation 定位、分享、Web 推送通知） |
| 团长端 | H5 页面（Vue3 / React） | 浏览器访问，响应式适配；调起分享与在线支付 |
| 运营后台 | PC Web（Vue3 / React + Element Plus / Ant Design） | 管理后台，支持复杂表格、数据可视化、权限控制 |
| 支付组件 | Web 支付（支付宝/微信 H5 支付） | Web 支付页面跳转，支持代金券、立减、代付 |

### 8.3 中台层

| 服务 | 职责 | 关键能力 |
|------|------|----------|
| 订单中心 | 订单全生命周期管理 | 状态机驱动、幂等性保障、分布式锁防超卖 |
| 商品中心 | 商品信息、分类、规格、价格 | 支持多规格矩阵、社区级商品池隔离 |
| 库存中心 | 实时库存扣减与预占 | 下单预占库存、支付成功后正式扣减、超时释放 |
| 营销中心 | 优惠券、会员、积分、拼团 | 券的创建/发放/核销/过期；会员等级计算；拼团状态机 |
| 调度中心 | 骑手派单与路径优化 | 基于距离与负载的自动派单；配送轨迹追踪 |
| 支付中心 | 在线支付对接与资金拆分 | Web 支付下单、回调处理、退款、佣金结算、对账 |
| 用户中心 | 用户信息、地址、会员、积分 | 手机号+密码登录/短信验证码登录、用户标签、画像计算 |
| 团长中心 | 团长档案、业绩、佣金、提现 | 佣金计算引擎、提现审批与打款 |
| 消息中心 | Web 推送通知、短信、站内信 | Web 推送通知/短信通知模板管理、推送限流 |

### 8.4 后台层

| 组件 | 方案 | 说明 |
|------|------|------|
| 应用框架 | Spring Cloud / Go 微服务 | 服务注册发现、配置中心、网关限流 |
| 数据库 | MySQL（主从 + 分库分表） | 订单表按用户 ID 分片；商品、用户、团长独立库 |
| 缓存 | Redis Cluster | 热点商品缓存、库存扣减（Redis 原子操作 + Lua 脚本）、用户会话 |
| 消息队列 | Kafka / RabbitMQ | 订单事件、支付回调、库存同步、佣金结算异步化 |
| 搜索引擎 | Elasticsearch | 商品搜索、订单检索、日志分析 |
| 文件存储 | OSS / 腾讯云 COS | 商品图片、用户头像、评价图片 |
| 地图服务 | 腾讯地图 SDK | 社区定位、地址解析、配送路径规划、骑手位置追踪 |
| 监控告警 | Prometheus + Grafana + 告警中心 | 服务 QPS、延迟、错误率；业务指标（订单量、支付成功率） |

### 8.5 数据流图

```
[用户 Web 应用] → API 网关 → 中台服务集群 → MySQL / Redis / Kafka
                                    ↓
                              [运营后台] ← 数据聚合服务 ← Elasticsearch
                                    ↓
                              [数据报表/BI]
```

### 8.6 安全设计

- **支付安全：** 支付回调验签，防止伪造回调；订单金额服务端计算，前端只传 SKU 与数量；敏感操作（退款、改价）需二次确认与审批
- **数据安全：** 用户手机号、地址加密存储（AES-256）；传输层 HTTPS 全链路；后台操作日志全量记录
- **权限安全：** RBAC 权限模型，菜单级与数据级双重控制；敏感接口限流防刷
- **库存安全：** Redis 分布式锁 + 数据库唯一索引防止超卖；库存扣减采用"预占+确认"两阶段模式

## 十、商业模式

### 10.1 收入来源

| 收入线 | 模式 | 预估占比 | 说明 |
|--------|------|----------|------|
| 商品差价 | 零售价 - 采购成本 | 50% | 标品粮油、日百综合毛利约 18%；生鲜引流品毛利可控，整体随规模上行 |
| 平台服务费（团长佣金抽成） | 从成交额中抽取，团长分佣后剩余部分 | 30% | 团长分佣 8-12%，平台净留成稳定，随订单量同步增长 |
| 品牌广告位 | Web 应用首页 Banner、搜索推荐、拼团位等 | 15% | 向品牌方开放 CPC/CPT 广告，月活达标后启动 |
| 增值服务 | 会员订阅、SaaS 输出、到家服务 | 5% | 远期收入，用户信任沉淀后逐步打开 |

### 10.2 成本结构

| 成本项 | 说明 | 优化方向 |
|--------|------|----------|
| 商品采购成本 | 从区域批发商/产地采购生鲜与日百 | 规模集采、以销定采降低损耗 |
| 前置仓租金 | 社区周边小型仓库（50-100㎡） | "小而密"策略，单仓租金控制在 5000 元/月以内 |
| 骑手配送成本 | 专职/兼职骑手按单计酬 | 拼团集中配送摊薄单均成本 |
| 团长佣金 | 按成交额 8-12% 分佣 | 差异化佣金率，高价值团长额外激励 |
| 技术运维成本 | 云服务器、带宽、支付手续费 | 微服务弹性伸缩，闲时降配 |
| 营销获客成本 | 新人券、拉新奖励 | 依赖团长裂变与社群自传播，控制获客成本在 5 元/人以内 |

## 十一、运营规划

### 11.1 冷启动策略

| 阶段 | 动作 | 目标 |
|------|------|------|
| 预热期（上线前 2 周） | 在社区门口/电梯投放海报，扫码加入社区群；群内每日预告"即将开业" | 建立 3 个 200 人以上的社区群 |
| 开业期（上线首周） | 新人首单立减 5 元、前 100 单免配送费、团长每日开团爆款 | 日订单破 50 单，首批用户完成首次体验 |
| 爬坡期（上线 2-4 周） | 推出"连续下单 7 天返积分""邀请邻居各得 3 元券"；团长每日社群互动 | 日订单稳定 80-100 单，7 日留存达 30% |

### 11.2 团长招募与培养

- **招募渠道：** 社区宝妈群、便利店/物业合作、老团长推荐、Web 应用内"申请成为团长"入口
- **招募标准：** 居住在本社区或相邻社区、有闲置时间、性格外向乐于助人、社区群成员数 200+ 或活跃社区群成员
- **培训体系：**
  1. 线上培训视频（Web 应用操作、开团流程、社群话术）
  2. 老团长带新（首周由经验丰富的团长一对一指导）
  3. 每周线上分享会（优秀团长经验分享）
- **激励机制：** 除基础佣金外，设置"月度之星"奖励（TOP3 团长额外奖金）、新团长首月保底佣金、推荐新团长奖励

## 十二、上线路线图

### 12.1 阶段划分

| 阶段 | 时间 | 目标 | 核心任务 |
|------|------|------|----------|
| Phase 1：单店验证 | 0-3 个月 | 验证模型可行性 | 选定 1 个试点社区；上线 Web 应用 MVP（首页、购物车、支付、订单）；招募 5 名种子团长；跑通"下单-支付-拣货-配送"闭环；日单量目标 100 单 |
| Phase 2：区域复制 | 3-9 个月 | 验证规模化能力 | 扩展至同城 30 个社区；建立 3-5 个前置仓；团长数突破 200 人；上线拼团、会员、团长工作台完整版；月 GMV 破百万 |
| Phase 3：城市打透 | 9-18 个月 | 建立区域壁垒 | 覆盖单一城市主流社区（100+）；供应链集中采购降本；上线会员订阅与增值服务；启动品牌广告变现；实现单城市盈利 |
| Phase 4：跨城复制 | 18 个月+ | 模式输出 | 进入新城市，复制已验证模型；开放团长 SaaS 平台（小商户零代码接入）；探索到家保洁、社区团购等延伸服务；启动融资扩张 |

## 十三、风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| 单社区订单量不足 | 中 | 高 | 严格控制试点社区选择标准（入住率、年轻家庭占比）；冷启动期加大补贴力度；团长未达到最低单量时及时更换 |
| 团长流失率高 | 中 | 高 | 设置首月保底佣金降低早期流失；建立团长社群增强归属感；优秀团长发展为"区域合伙人"提升粘性 |
| 生鲜损耗过高 | 中 | 中 | 以销定采，首期限量上架高损耗品类；每日盘点库存，临期商品及时转拼团清仓；与供应商约定可退换货 |
| 配送超时导致用户体验差 | 高 | 中 | 前置仓密度优先于面积，确保覆盖半径可控；高峰期增加兼职骑手；设置超时自动赔付机制，降低用户怨气 |
| 食品安全事故 | 低 | 极高 | 严格供应商准入（营业执照、食品经营许可证、检测报告）；建立问题商品追溯机制；购买食品安全责任险 |
| 支付接口异常 | 低 | 高 | 支付回调增加重试与补偿机制；运营后台支持手动标记支付状态；准备客服话术引导用户重新支付 |
| 竞品低价补贴抢市场 | 高 | 中 | 不跟进价格战，强化"即时达+人情味"差异化；通过团长关系与社群粘性提升用户转换成本 |
| 政策监管（社区团购限制） | 低 | 高 | 合规经营，不倾销、不补贴扰乱市场；与社区物业建立良好关系；关注政策动态及时调整 |
